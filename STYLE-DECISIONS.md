# STYLE-DECISIONS.md — Engineering Judgement Calls

1. **Deliberate Spec Extension — `TokenRule` `{ ref: "bg" }`**: Allowed `{ ref: "bg" }` in `TokenRule` because `neon` and `retro` define `dark` as identical to `bg`, evaluated after `bg` in fixed token resolution order.
2. **Deliberate Spec Extension — Object Form for `motion.ease`, `motion.enter`, `motion.exit`**: Allowed `{ text?: string; default?: string }` in `motion.ease`, `motion.enter`, and `motion.exit` so `retro` can specify `linear` / `typeOn` for text layers and `outQuad` / `glitch` for other layers.
3. **Deliberate Spec Extension — `text.outline.displayOnly`**: Added `displayOnly?: boolean` to `text.outline` so `comic` outlines only layers using the pack's `display` font family.
4. **Deliberate Spec Extension — `motion.slamShake`**: Added `slamShake?: { dur: number; amp: number }` to `pack.motion` so `comic`'s deterministic camera shake on `slam` macros is data-driven rather than hard-coded to a pack ID.
5. **Neutral Accent Saturation Exception (`s === 0`)**: When an accent's HSL saturation is `0` (such as `retro` palette 5 `#E6E6E6`), `accentRule.sMin` is skipped (`s = 0`) and derive rules without an explicit `h` keep `s = 0` so monochrome palettes stay neutral and pass WCAG contrast (`muted #808080 on bg #0D0D0D = 4.92:1 >= 4.5:1`).
6. **Minimal Integer `L` Contrast Adjustment for Built-In Pack Accents (§5.1)**: Adjusted failing built-in accent `L` values by the smallest integer multiple of 1 so all 5 required WCAG contrast pairs pass (`light` p2 `L: 42->28`, p4 `L: 42->30`, p5 `L: 48->42`; `paper` p1 `L: 54->46`, p2 `L: 45->39`, p3 `L: 58->35`, p4 `L: 46->33`; `comic` p3 `L: 50->34`, p4 `L: 50->34`) and locked all resolved tokens in `tests/goldens/neon-baseline/pack-tokens-snapshot.json`.
7. **Token Count Consistency**: Preserved the exact 22 token keys in `PALETTE_TABLE` (`20 derive + acc + warn = 22`) plus backward-compatible alias keys (`card`, `cardBorder`, `cardStroke`, `hero`, `accSoft`, `warnBg`, `sub`, `line`) so `neon` palettes 1–5 and custom hexes match legacy v3.1 `expandThemeTokens` byte-for-byte.
8. **Neon Pixel-Identical Guarantee**: For `styleId === "neon"` and `palette` 1–5, `resolveTokens` returns `PALETTE_TABLE[palette]` verbatim, and for `styleId === "neon"` with custom `hex`, `resolveTokens` delegates to `legacyExpandNeonHex` so all 12 sample hexes and S0 goldens match byte-for-byte.
9. **Surface Texture Composite Modes (§8.2)**: Used `globalCompositeOperation = "multiply"` for `paper`, `"multiply"` for `halftone` (`@ink` at alpha `0.10` inside surfaces, `@acc` at alpha `0.12` on canvas backdrop), and `"multiply"` for `scan` (`1 px` horizontal lines every `3 px` scaled by `canvasW / 1920` at alpha `0.12` in `@ink`).
10. **Boilerplate `global.vignette: 0.6` Handling on Restyle**: Because v3.1 sample recipes include `"global": { "vignette": 0.6 }` as boilerplate default, `applyPostEffects` uses `pack.post.vignette` for non-neon packs unless `global.vignette` explicitly differs from the `0.6` boilerplate default, ensuring `light` (`vignette: 0.06`) and `comic` (`vignette: 0`) maintain clean bright backgrounds when restyling existing v3.1 recipes.
11. **Prompt Pack Synchronization**: Both `src/assets/prompt-pack.txt` and `src/assets/promptPack.ts` are updated in lockstep so runtime imports and raw asset tests see identical text; `src/assets/style-pack-maker.txt` is mirrored in `src/assets/stylePackMaker.ts` for offline clipboard copy.
12. **IndexedDB `stylepacks` Store Compatibility**: Added `STORE_STYLEPACKS = "stylepacks"` (`DB_VERSION = 3`) while keeping `IDB_STORE_NAMES` as the 7 core v3.1 stores expected by existing M17 tests, paired with an in-memory map fallback for headless Node test execution.
